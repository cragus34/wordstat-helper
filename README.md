## 1. Контекст и цель

SEO-редакторы тратят значительное время на ручной сбор семантики: нужно собрать фразы по маске из Яндекс Вордстата, затем отдельно проверить их частотность в сервисе json seo. Это рутинный двухэтапный процесс без автоматизации.

**Цель проекта:** создать веб-инструмент, который автоматически собирает список фраз по seed-маске из Яндекс Вордстата и обогащает их двумя видами частотности из json seo — базовой и точной ("!слово !слово"). Результат выводится в таблицу и экспортируется в Excel.

**Пользователи:** SEO-редакторы без технических навыков. Работают через браузер.

| | |

## 3. Функциональные требования

| # | Требование |
|---|---|
| ФТ-01 | Система принимает на вход: seed-фразу, мин. частотность (число), список стоп-слов |
| ФТ-02 | Система возвращает таблицу с колонками: фраза, базовая частотность, точная частотность ("!слово !слово") |
| ФТ-03 | Фразы с базовой частотностью ниже минимального порога не включаются в результат |
| ФТ-04 | Фразы, содержащие хотя бы одно стоп-слово (без учёта регистра), исключаются |
| ФТ-05 | Парсинг ведётся постранично; останавливается, как только минимальная базовая частотность на странице опускается ниже порога (список Вордстата отсортирован по убыванию — дальше только хуже) |
| ФТ-06 | Точная частотность ("!слово !слово", kind="exact") запрашивается только для фраз, прошедших фильтрацию |
| ФТ-07 | Отображение прогресса: фоновая обработка задачи с индикатором процентов и текущего этапа (страницы Wordstat -> сбор точной частотности N из M) |
| ФТ-08 | Возможность принудительной остановки сбора (кнопка «Остановить сбор»): процесс немедленно прерывается, не тратит лишние запросы/баланс API; уже собранные к этому моменту фразы сохраняются и выводятся |
| ФТ-09 | Непрерывное сохранение в SQLite: запись в БД создаётся в момент старта, данные записываются по мере сбора каждой фразы; при случайной перезагрузке страницы статус подхватывается автоматически из браузера без потери прогресса |
| ФТ-10 | Сортировка результатов в интерфейсе и при выгрузке в Excel по умолчанию производится по убыванию точной частотности |
| ФТ-11 | Если API недоступен — система возвращает понятное сообщение об ошибке, не падает |
| ФТ-12 | Результаты таблицы экспортируются в файл .xlsx: файл именуется по маске (`wordstat_{маска}_{id}.xlsx`), внутри содержит заголовок с ключевой фразой, дату сбора и число фраз |
| ФТ-13 | Каждый запрос сохраняется в историю: маска, дата/время, статус (завершён/остановлен), кол-во итоговых фраз, полная таблица |
| ФТ-14 | История отображается списком; клик по записи открывает сохранённую таблицу |

## 5. Стек технологий

| Компонент | Решение |
|---|---|
| Бэкенд | Python 3.11, FastAPI |
| Фронтенд | HTML + Tailwind CSS (без отдельного SPA) |
| База данных (история) | SQLite (локально, не требует отдельного сервера) |
| Внешние API | **json seo API** — единственный внешний источник данных. Закрывает всё: `/wordstat` (список фраз по маске + базовая частотность), `/wordstat/frequency?kind=superexact` (суперточная частотность). Яндекс Search API не используется. |

| Экспорт | `openpyxl` (генерация .xlsx) |
| Развёртывание | Docker + Docker Compose |

> [!NOTE]
> SQLite выбрана для истории запросов как наиболее простое решение для 1–10 пользователей.
> При росте нагрузки заменяется на PostgreSQL без изменения бизнес-логики (через SQLAlchemy).

## 6. Архитектура (высокий уровень)

**Единственный внешний API:** json seo. Закрывает и парсинг фраз, и сбор частотности.

```
Браузер (HTML-форма)
       │  POST /api/run-parsing
       ▼
   FastAPI (main.py)
       │
       ├──► JsonSeoWordstatClient
       │       │
       │       ├─ GET /wordstat?text=маска&page=1  →  50 фраз + базовая частотность
       │       ├─ GET /wordstat?text=маска&page=2  →  50 фраз + базовая частотность
       │       └─ ...стоп, если min(base_freq на странице) < порога  [вариант B]
       │
       ├──► FilterService
       │       └─ исключить фразы < min_freq и содержащие стоп-слова
       │
       ├──► JsonSeoFrequencyClient
       │       └─ GET /wordstat/frequency?text=фраза&kind=superexact  (× N фраз)
       │
       └──► HistoryRepository  →  SQLite
```

**Логика остановки пагинации (вариант B):**
Список фраз в Вордстате отсортирован по убыванию базовой частотности.
Как только последняя фраза на странице имеет `value < min_freq` — дальше собирать нет смысла, все следующие страницы тоже будут ниже порога. Останавливаемся.

Это экономит запросы к API и деньги: вместо всегда 20 страниц — только нужные.

## 7. API-контракт

### POST `/api/run-parsing` — запустить сбор

**Запрос:**
```json
{
  "seed_phrase": "каркасная баня",
  "min_freq": 100,
  "stop_words": ["цена", "недорого"]
}
```

**Ответ — успех:**
```json
{
  "status": "success",
  "query_id": "a1b2c3",
  "data": [
    {
      "phrase": "каркасная баня под ключ",
      "base_freq": 4200,
      "super_exact_freq": 120
    }
  ]
}
```

**Ответ — ошибка:**
```json
{
  "status": "error",
  "code": "YANDEX_API_UNAVAILABLE",
  "message": "Яндекс API временно недоступен. Попробуйте через минуту."
}
```

---

### GET `/api/history` — список запросов

**Ответ:**
```json
{
  "status": "success",
  "data": [
    {
      "query_id": "a1b2c3",
      "seed_phrase": "каркасная баня",
      "created_at": "2026-10-25T12:00:00",
      "phrase_count": 47
    }
  ]
}
```

---

### GET `/api/history/{query_id}` — результаты конкретного запроса

**Ответ:** аналогичен успешному ответу `/api/run-parsing`.

---

### GET `/api/export/{query_id}` — скачать Excel

**Ответ:** файл `wordstat_{query_id}.xlsx` (Content-Type: application/vnd.openxmlformats).

## 9. Известные ограничения

| # | Ограничение | Причина |
|---|---|---|
| ОГ-01 | Суперточная частотность может расходиться с реальным Вордстатом на 1–2 показа | json seo отдаёт данные из своего кэша, а не в реальном времени. Для сравнения фраз между собой это некритично — соотношения сохраняются |
| ОГ-02 | Пагинация ограничена 20 страницами (~1000 фраз) | Лимит json seo API |
| ОГ-03 | Суперточная частотность запрашивается по одной фразе, без батча | Батч-метода в json seo API нет; при 100 фразах — 100 последовательных запросов |

## 9. Открытые вопросы (нужно уточнить перед разработкой)

| # | Вопрос | Влияние |
|---|---|---|
| ~~ОВ-01~~ | ~~Какой метод Яндекс Wordstat API возвращает список фраз по маске?~~ | ✅ Закрыт: json seo `/wordstat` — возвращает `results.popular` (популярные) и `results.associations` (похожие) запросы с частотностью (`value`). Это и есть список фраз по маске. Яндекс Search API в итоге не нужен — json seo закрывает обе задачи. |
| ~~ОВ-02~~ | ~~Как json seo API принимает запросы на частотность: по одной фразе или батчем?~~ | ✅ Закрыт: `/wordstat/frequency` принимает **одну фразу за запрос**, возвращает `results.totalValue`. Батча нет. При 100 фразах — 100 последовательных запросов (0.01 ₽ каждый = 1 ₽ на сессию). Возможная оптимизация: `asyncio` для параллельных запросов. |
| ~~ОВ-03~~ | ~~Базовая частотность: её возвращает Яндекс Wordstat или json seo?~~ | ✅ Закрыт: Яндекс Wordstat возвращает список фраз + базовую частотность в одном ответе. json seo используется только для суперточной. Фильтрация по порогу происходит на данных Яндекса, до запросов в json seo. |

## 10. Критерии приёмки (Definition of Done)

- [ ] При маске «каркасная баня» и порогe 100 — таблица содержит реальные данные из Яндекс и json seo
- [ ] Стоп-слово «цена» убирает все фразы с этим словом из таблицы
- [ ] Фразы с частотностью < 100 в таблицу не попадают
- [ ] Кнопка «Скачать Excel» скачивает корректный .xlsx с данными текущей таблицы
- [ ] История сохраняется между перезапусками сервиса
- [ ] Если один из внешних API недоступен — пользователь видит сообщение, не белый экран
- [ ] API-ключи не захардкожены в коде
- [ ] `docker compose up` поднимает сервис без дополнительных действий
